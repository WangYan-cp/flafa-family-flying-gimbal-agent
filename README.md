# FLAFA 家庭飞行云台 AI辅助拍摄Agent

**FLAFA Family Flying Gimbal AI-Assisted Shooting Agent**

> Public documentation repository · 项目介绍与技术资料公开仓库

## 项目简介

FLAFA家庭飞行云台AI辅助拍摄Agent面向家庭内容创作者与普通家庭记录者，针对持续操控设备、多人同框困难及关键内容容易遗漏等问题，构建“自然语言表达需求—Agent理解与规划—安全约束下执行—用户随时接管”的AI辅助拍摄体验。整体产品方案由飞行云台原型、手机端App与AI拍摄Agent组成，规划支持多人跟拍、语音与手势交互、AI辅助剪辑等能力；当前仓库重点呈现Agent软件架构、真实模型接入、Runtime、安全规则、仿真环境及专项评测成果，真实飞控、定位与完整硬件闭环仍在持续推进。

### 整体产品方案

手机是主要成像设备，飞行云台用于扩展手机可到达的拍摄机位。整体方案围绕家庭持续记录设计，包括飞行云台原型、手机端App、AI拍摄Agent、多人跟拍、语音与手势交互、AI辅助剪辑与内容生成等能力。产品以横屏记录为主，同时支持竖屏拍摄。

这一层描述的是完整产品方向，其中既包含已完成的软件与原型机能力，也包含验证中和规划中的模块；各模块的实际进度以“当前实现状态”为准。

### 当前仓库进度

本公开仓库主要呈现Agent的软件架构、Context与记忆体系、真实模型接入、结构化ShootingPlan、确定性Planner、Runtime、Safety Supervisor、任务回滚、仿真环境和专项评测结果。完整业务源代码、运行凭据及内部工程资料保留在私有工程仓库。

> 核心边界：语言模型只生成高层拍摄策略、结构化ShootingPlan和候选ID，不直接生成真实坐标、速度、轨迹、避障决策或飞控指令。机位ID解析、可达性判断、安全裁决、任务编译与回退由确定性系统及后续硬件执行域负责。

## 项目解决什么问题

- 调整镜头和切换机位会中断活动，拍摄者也难以自然参与。
- 手持、自拍和固定支撑难以持续覆盖丰富视角、多人同框及儿童平视机位。
- 固定与灵活机位需要随活动变化衔接，单纯硬件仍依赖用户持续判断。
- 普通跟踪只回答“目标在哪里”，不能理解“为什么拍、重点是什么、何时调整”。
- 家庭拍摄涉及人物关系、活动阶段和关键瞬间，只追踪单一主体容易遗漏重要内容。
- 每次拍摄都要重新说明人物、空间和偏好，已确认经验难以在用户控制下复用。
- 专业拍摄参数学习成本高，用户更希望直接表达记录目标。

## 为什么是Agent

大语言模型是Agent的规划能力之一。一次性模型调用可以生成建议，但不能单独维护用户授权记忆、任务事实、受控候选、确认版本、安全状态和持续运行反馈。FLAFA将自然语言理解、M1–M6记忆体系、Context Builder、Condition分支、结构化规划、确定性解析、安全门控、用户确认和Runtime组织为可追溯闭环。

因此，Agent负责理解“拍什么、为什么拍、重点是什么”，并形成高层拍摄方案；确定性系统负责把受控候选转化为可检查、可暂停、可回滚的任务。二者不是相互替代的方案，而是语义规划与受控执行之间的分工。

## 核心产品能力

以下内容描述整体产品设计，不代表每项能力都已在当前公开仓库或当前版本中完成。

- **三类场景化拍摄模式**：日常固定记录、动态互动记录、重要事件记录。
- **自然语言记录意图理解**：用户通过语音或文字说明人物、空间、时长与记录重点，Agent在信息不足时进入Condition分支并追问缺失项。
- **结构化ShootingPlan**：把自然语言目标转为可校验、可确认、可版本化的高层拍摄方案，只引用受控候选ID。
- **六类记忆与Context Builder**：M1家庭人物与关系、M2家庭空间与拍摄锚点、M3用户影像偏好、M4拍摄事件与经验、M5常用方案、M6当前任务状态；仅按当前任务权限检索必要信息，形成版本化Context Package。
- **家庭场景理解**：在用户授权范围内组织家庭成员关系、空间机位、影像偏好和历史记录，减少重复设置。
- **多人跟拍与人物切换**：根据活动阶段与叙事重点保持主体、切换人物或调整候选机位，而不是只执行单目标跟踪。
- **App、语音与手势交互**：App承担需求确认与用户接管；语音是当前主要自然交互方式，手势属于后续交互方向。
- **AI辅助剪辑与内容生成**：规划把拍摄事件、关键片段与结构化任务记录用于后续素材整理、剪辑和内容生成。
- **安全与可接管运行**：通过CP0–CP4检查点、Safety Supervisor、任务回滚、用户确认、暂停、取消和安全降级，保证模型建议不能绕过确定性约束直接控制硬件。

## 阶段性验证结果

阶段性验证中，项目完成6类家庭场景、共60轮原型机测试，主体保持和多人跟踪任务成功率分别为94%和89%；选取18段原型机实拍样片，由24名目标用户进行受控盲评，运镜平滑感与画面质量平均评分分别为4.6和4.4分（5分制）。同期完成T01–T08真实模型用例及S01–S03安全规则专项检查，分别8/8和14/14通过。

## 能力边界

- 当前项目不是开放域全自主飞行系统。
- Agent负责理解需求、生成高层拍摄方案、结构化ShootingPlan并选择候选工具或候选ID。
- 确定性系统负责机位ID解析、可达性判断、安全裁决、任务编译、状态一致性与回退。
- 用户保留确认、暂停、取消、结束和接管权限；高风险或事实不足时，系统应追问、降级、暂停或拒绝。
- 当前软件与仿真测试通过，不等于已经完成真实飞控、安全认证、续航验证或量产验证。
- 整体产品能力与当前仓库实现进度应分开理解，具体状态以“当前实现状态”表为准。

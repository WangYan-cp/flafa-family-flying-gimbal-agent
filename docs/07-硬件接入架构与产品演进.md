# Hardware Integration｜硬件接入架构与产品演进

从软件先行工程版到家庭飞行云台联合研发 | Hardware Integration Reference｜硬件接入说明 | 2026-08-18

## 1. 硬件连接点

LLM 不直接连接硬件。Hardware Adapter 接收通过确定性解析、安全审查和用户确认的 ShootingTask；任务包含计划版本、视点引用、路径引用、相机配置、时长、安全约束和备用策略。真实坐标、速度、姿态和电机参数由本地定位、路径规划和设备控制模块解析。

手机是主要拍摄设备，飞行云台承担手机承载和机位扩展。产品以横屏拍摄为主，以保留更完整的环境和人物关系，同时支持竖屏。手机与硬件的主要绑定方向为 NFC：触碰识别与绑定、建立连接、完成权限和设备状态检查、进入就绪，最后仍由用户确认开始。对外表述为“一碰绑定，快速就绪”，不等同于触碰后自动起飞。

## 2. 设备反馈

Hardware Event 覆盖连接、周期性在线与连接状态（Heartbeat）、电量、温度、定位质量、地图版本、路径阻挡、禁飞边界、云台/相机状态、开始、暂停、恢复、完成、返航、降落与紧急停止。事件需要唯一 ID、观察时间、设备状态版本、来源和错误码，以支持幂等、排序、审计和恢复。

## 3. 联合验证路线

1. Contract Simulator｜合同模拟：验证 ShootingTask、Hardware Event、版本、幂等与错误。
2. Static Bench｜静态台架：验证云台、相机、暂停、停止、电量、温度和错误回传。
3. Restricted Space｜受限空间：接入定位、地图、低速路径、避障和禁飞边界。
4. Dynamic Task｜动态任务：验证跟拍、主体离开、显著切换、Checkpoint 回滚和恢复。
5. Long-run & Fault Injection｜长时间与故障注入：验证断连、低电、过热、上游失败与人工接管。

## 4. 工程边界

- 不从模型文本解析坐标或电机命令。
- 不允许前端绕过 Orchestrator 直接调用飞控。
- 不因视觉预览成功而跳过 Safety。
- 不复用过期地图、路径、电量和定位状态。
- 不把软件评测直接等同于硬件安全、续航或量产认证。

## 5. 产品演进方向

v8.4.0 已形成 Agent 软件闭环。后续硬件研发将在保持用户确认、安全否决和模型权限边界的前提下，逐步接入手机承载、云台、飞控、定位、路径和避障能力。语音是当前主要交互方式；手势是后续交互适配方向，二者都不会绕过 Orchestrator 与 Safety 直接控制飞行。

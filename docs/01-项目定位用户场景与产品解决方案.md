# 项目定位、用户场景与产品解决方案

FLAFA 家庭飞行云台 AI 辅助拍摄 Agent | Product Overview｜产品说明 | 2026-08-18

> FLAFA 面向以家庭内容创作者为核心、同时覆盖普通家庭记录者的持续家庭影像场景。用户只需表达想记录的人、空间、时长和重点，Agent 负责组织任务信息、记忆、现实事实、拍摄方案与运行变化；手机仍是主要成像设备，飞行云台用于扩展手机能够到达的机位，用户始终保留确认与接管权。

## 1. 用户画像与需求场景

FLAFA 的核心用户，是希望在自然亲子互动中轻松捕捉真实成长瞬间的家庭内容创作者；同时也服务希望降低拍摄负担、完整保留家庭日常的普通家庭记录者。用户既是影像创作者，也是家庭活动参与者，不应持续被手机、机位和参数操作束缚。

| 维度 | 场景定义 |
|---|---|
| 主要拍摄设备 | 手机；飞行云台将手机带到更合适的拍摄位置 |
| 画面方向 | 以横屏为主，以获得更完整的环境、人物关系和活动画面；同时支持竖屏拍摄 |
| 常见内容 | 写作业、阅读、做饭、手作、生日、用餐、亲子活动、宠物陪伴和多人互动 |
| 记录特征 | 以较长时间的室内记录和较短时间的室外记录为主，叙事重点会随活动变化 |
| 用户角色 | 拍摄者本身也是活动参与者，希望减少操作、释放双手并进入画面 |

## 2. 用户痛点：为什么需要新的拍摄方式

| 用户痛点 | 手机、手持或固定云台的限制 | 用户需要的结果 |
|---|---|---|
| 调整镜头会中断活动 | 切换视角、改变位置时需要离开活动去调整设备 | 在不中断家庭活动的前提下切换拍摄视角 |
| 双手被持续占用 | 手持拍摄需要持续取景和操作 | 解放双手，让拍摄者自然参与活动 |
| 自拍视角互动有限 | 拍摄者容易停留在画面之外，人物互动和视角单一 | 提升参与感，并获得更丰富的观察角度 |
| 固定与灵活机位难协同 | 固定机位覆盖有限，手持机位又需要持续操作 | 固定与灵活机位可以按任务需要衔接 |
| 儿童平视视角获取困难 | 成人需要长期蹲下或反复调整高度 | 更自然地获得儿童平视和低机位视角 |
| 普通跟踪缺少拍摄语义 | 只能判断“目标在哪里”，不能理解“为什么拍、重点是什么、何时调整” | 系统结合人物、关系、活动、空间和叙事目标组织拍摄 |
| 每次都要重新设置 | 偏好、家庭空间和成功方案分散，下一次仍需从头说明 | 在用户授权下复用必要记忆和已确认方案 |
| 专业拍摄学习成本高 | 用户需要理解镜头、机位、构图和切换参数 | 用自然语言表达目标，由系统转化为拍摄方案 |

## 3. 为什么需要飞行云台

手机具备成熟的成像、通信和内容生产能力，但手持或固定支撑限制了它能够到达的高度、距离和观察角度。飞行云台的产品作用不是替换手机，而是把手机带到更合适的拍摄位置，在保留熟悉设备与内容工作流的同时，扩展固定、移动、儿童平视和多角度拍摄能力。

飞行云台解决物理机位和视角问题，但“能移动”并不等于“会拍”。如果系统不能持续理解拍谁、为什么拍、何时调整以及变化后如何处理，用户仍需不断操控。因此，飞行云台需要与 Agent 的任务理解和持续协拍能力配合。

## 4. 为什么需要 Agent，而不是一次性大模型调用

大语言模型是 FLAFA Agent 的规划能力之一，而不是独立承担整个拍摄系统。一次性模型调用可以提供建议，却不能单独维护家庭拍摄任务需要的记忆、事实、候选、确认版本、安全状态和运行反馈。

| 任务要求 | 一次性大模型调用的局限 | FLAFA Agent 的设计 |
|---|---|---|
| 用户信息不足 | 容易猜测或一次性生成完整答案 | 只追问当前任务缺少的信息，并保留多轮上下文 |
| 家庭事实和拍摄目标 | 主要处理当前提示词 | 构建最小、版本化 Context Package，区分目标、记忆、事实和候选 |
| 复用家庭经验 | 难以稳定处理可写入、可纠正和可删除的长期信息 | 用 M1-M6 记忆分类管理人物、空间、偏好、经验、常用方案和当前任务状态 |
| 拍摄方案输出 | 生成自然语言建议 | 生成结构化 ShootingPlan，并只选择系统提供的候选 ID |
| 物理执行 | 不能保证文本可直接执行 | 由确定性模块解析视点与路径，并完成合同、条件和安全校验 |
| 场景持续变化 | 对话结束后不再跟踪现实状态 | Runtime Monitor 根据人物、设备、环境和任务变化刷新或重规划 |
| 用户控制 | 一次问答通常没有完整控制闭环 | 保留确认、暂停、恢复、取消、结束和必要的回滚 |
| 可追溯性 | 结果难以对应当时事实和版本 | Context、Plan、Task 和 Runtime State 均带来源与版本 |

Agent 的价值不是让模型直接控制飞行，而是把自然语言理解、用户授权记忆、任务上下文、受控规划、确定性执行、安全门控和运行反馈组织成持续工作的协拍系统。

## 5. 当前 Agent 软件解决方案

1. 用户以语音为主、文字为回退方式，描述拍摄对象、空间、时长和希望记录的内容。
2. 信息不足时，Agent 只追问缺失项，不用猜测补齐家庭事实。
3. Context Builder 从用户授权记忆、当前事实和受控候选中，形成当前任务所需的最小、版本化 Context Package。
4. LLM Planner 生成语义 ShootingPlan，并只选择工具提供的候选 ID。
5. 确定性模块解析视点和路径，完成结构、条件与安全校验。
6. 用户确认后，Task Compiler 才生成 ShootingTask 并交给 Hardware Adapter。
7. Runtime Monitor 根据人物、设备、环境、路径和画面变化决定保持、刷新、重规划、暂停或回滚。
8. 任务结束后，只在符合写入规则并由用户确认时保存必要的记忆或方案摘要。

## 6. 需求、功能设计与当前范围

| 用户需求 | 对应功能设计 | 当前对外说明范围 |
|---|---|---|
| 降低学习成本和操作负担 | 语音/文字输入、缺失信息追问、需求确认 | v8.4.0 软件已实现；现阶段以语音为主要自然交互方式 |
| 让系统理解拍摄重点 | Context Builder、Qwen Planner、结构化 ShootingPlan | v8.4.0 软件已实现 |
| 记住必要的家庭信息与经验 | M1-M6 记忆分类、权限过滤、写入确认、纠正与删除边界 | 完整记忆架构已定义；当前实现范围见 05，详细规则见 03 |
| 在变化中保持拍摄任务 | Runtime Monitor、Context 刷新、重规划、Checkpoint | v8.4.0 软件已形成运行闭环 |
| 在执行前保持可控 | Schema、Condition、Safety、用户确认、Task Compiler | v8.4.0 软件已实现并完成专项验证 |
| 帮助用户理解方案 | Wan 视觉表达与方案预览 | v8.4.0 软件已实现；预览不等同于真实相机画面 |
| 获得固定、灵活及儿童平视机位 | 候选视点、确定性解析和 Hardware Adapter | 属于硬件研发接入方向，本资料不宣称已经完成真实飞行执行 |
| 降低现场交互负担 | 语音为当前主要方式；手势作为后续交互适配方向 | 手势不列为 v8.4.0 已实现能力 |

## 7. 安全执行原则

为了让移动拍摄过程中的物理执行可验证、可约束并可由用户接管，FLAFA 将语义规划与硬件执行分层。LLM 生成高层 ShootingPlan 并选择受控候选 ID；坐标、路径、速度、避障和设备控制命令由确定性系统与硬件执行域产生。这是工程执行边界，不是用户痛点。

## 8. 产品价值

| 产品价值 | 用户感受到的变化 |
|---|---|
| 更轻松参与 | 从持续调整设备转为表达记录目标，拍摄者能够回到家庭活动本身 |
| 更懂你与拍摄意图 | Agent 在用户授权下结合人物关系、家庭空间、影像偏好、历史经验和当前事实，理解“为什么拍、重点是什么” |
| 持续智能协拍 | 系统从澄清、规划、确认一直工作到运行变化、调整和完成，而不是只给出一次建议 |
| 方案透明、执行可控 | 用户可以查看、修改和确认方案，并保留暂停、恢复、取消和结束权；模型不直接控制硬件 |
| 更低门槛与成本 | 语音降低学习成本，NFC 方向降低连接成本，复用手机降低独立成像设备和多设备协作成本 |
| 更丰富、连续的视角 | Agent 根据任务组织候选视点；后续飞行云台扩展手机可达机位，减少因移动设备造成的拍摄中断 |

## 9. 当前定位

FLAFA v8.4.0 是面向家庭飞行云台硬件接入的 AI 辅助拍摄 Agent 已开发软件版本。当前对外方案以 Agent 软件能力为主，已经形成任务理解、上下文、规划、校验、安全、运行时、真实模型与交互展示的软件闭环。手机承载、云台、飞控、定位、路径和避障等硬件能力属于后续联合研发接入范围，通过 Hardware Adapter 与当前 Agent 软件衔接。
